## 0. 墨刀（modao）插件状态与授权入口

当前会话未暴露 `mcp_modao` 工具，插件配置为：

- `.trae-cn/plugins/trae-remote-official/modao/0.1.0/.mcp.json`：MCP 地址 `https://modao.cc/agent-py/ai/mcp`，请求头需要 `modao-token: ${connector.modao.ACCESS_TOKEN}`
- `.trae-cn/plugins/trae-remote-official/modao/0.1.0/connector.json`：`type: manual_token`，`auth_policy: ON_INVOKE`

即：**缺少墨刀访问令牌，工具未注册，无法调用墨刀 AI 生成 PRD / HTML 原型 / 图片。**

授权步骤（任一即可）：

1. 在 Trae 中打开 **设置 → MCP / 插件连接器 → 墨刀（modao）→ 授权**，粘贴墨刀访问令牌（墨刀个人中心 / 开放平台获取）。
2. 或在本项目 `.trae/mcp.json` 中声明：

```json
{
  "mcpServers": {
    "mcp_modao": {
      "url": "https://modao.cc/agent-py/ai/mcp",
      "headers": { "modao-token": "<你的墨刀访问令牌>" }
    }
  }
}
```

授权后可用墨刀生成正式设计稿；本方案与 `prototype.html` 已覆盖同等目的，后续可直接把页面结构迁移进墨刀画板。

## 3. 视觉方向

### 3.1 定位

现有 report.py 已经建立了一套完成度较高的“纸本观测（Observation Ledger）”视觉语言。优化**不推翻它**，而是把它从“报告样式”升级为“桌面数据终端的完整设计系统”：

- **纸面 + 墨线 + 朱红**：低饱和纸色承载数据，1px 发丝线分隔，朱红只用于“当前/进行中/关键动作”。
- **常规无衬线数字 + 等宽小标签 + 无衬线正文**：数字与正文统一用雅黑，保证读数清晰；英文小标题用等宽大写保留仪表感。
- **克制的动效**：只用于状态变化（进度、吐司、抽屉），不做装饰动画；桌宠使用 GIF 帧循环（采集时加速）。

### 3.2 设计令牌（沿用并补齐）

```text
纸面      --paper      #F3EEE2   --paper-2  #FBF7EC   --paper-3 #EAE2D1
墨色      --ink        #1E1B16   --ink-soft #4A4337   --muted   #8A8071
分隔      --hairline   #DCD2BD   --hair-strong #C6BAA1
强调      --vermilion  #B3402A   --teal     #2F6159   --gold    #A98A4B
语义      ok=teal  busy=gold  error=vermilion  muted=#8A8071
```

新增语义约定：

- 互动增量正负：沿用 `UP=#A5372A`、`DOWN=#2F6159`，但**同时给出 +/− 符号**，不只靠颜色。
- 焦点环：`2px solid #B3402A`，`outline-offset: 2px`，所有可交互元素统一。
- 圆角统一 2px；仅弹层/抽屉允许阴影 `0 24px 60px -32px rgba(30,27,22,.45)`。

### 3.3 字体级联

| 角色 | 字体 | 规格 | 用途 |
| --- | --- | --- | --- |
| Display | Georgia / 宋体 | 28–40 / 700 / -0.02em | 页面标题、KPI 大数字 |
| H2 | Georgia / 宋体 | 22–24 / 700 | 卡片标题 |
| H3 | 微软雅黑 UI | 15 / 700 | 区块标题 |
| Body | 微软雅黑 UI | 13 / 400 / 1.7 | 正文、表格内容 |
| Small | 微软雅黑 UI | 11 / 400 | 辅助说明 |
| Label | Consolas | 9–10 / 大写 / 0.16em | 栏目序号、状态、时间、单位 |
| Num | Consolas / 衬线 | 26–34 / 700 / tabular | 统计数字 |

### 3.4 栅格与间距

- 桌面默认 1180×780，最小 980×660（现有 960×640 提升）。
- 左栏 236px 固定；内容区最大 1080px，左右留白 32px。
- 间距阶梯：4 / 8 / 12 / 16 / 20 / 24 / 32 / 48。
- 12 列栅格；卡片内边距 20–22px；表格行高 38–40px（较现有 27px 更易点选）。

## 4. 信息架构重组

**现状**：平台 Tab → 单页（统计带 + 帖子表）；设置/报告是弹窗与动作按钮。

**优化后**：

```text
桌宠（常驻）
  └─ 双击 / 右键“打开观测台”
       └─ 观测台窗口
            ├─ 01 观测台        当前平台：库存指标 + 时效心跳 + 帖子流水
            ├─ 02 运行监控      本轮进度、平台状态、冷却倒计时、事件日志
            ├─ 03 数据分析      区间 KPI、热力图、每日/每小时曲线、Top3 增长
            ├─ 04 评估报告      生成、历史列表、口径预览、浏览器打开
            └─ 05 设置          平台与账号、凭据、过滤、调度（抽屉/整页，不再模态）
            └─ 平台范围（左栏底部）带状态点的六平台切换
```

关键变化：

1. 平台**从“导航”降级为“数据范围”**，固定在左栏底部，带状态点（启用/停用/未配置/冷却）。
2. 报告、运行状态从“瞬时动作/一行文字”升级为**独立可追溯页面**。
3. 设置从模态改为**整页双栏**（左平台列表、右分区表单、底部保存条）。
4. 全局状态条常驻底部，吐司只承担“刚发生”的反馈。

### 5.2 01 观测台

**目标**：3 秒内回答“这个账号现在有多少数据、最近有没有变化、下一步做什么”。

结构：

```text
标题「账号数据观测」              [采集当前] [采集全部] [生成报告]  设置
说明：X @handle · 本轮互动 +128 · 上次 19:40 · 下次 20:10

账号条：粉丝 1204 · 关注 312 · 帖子 486 · 获赞 8921     [已启用] [会话有效]

库存指标（衬线大数字，4 格）        时效心跳（3 格 + 迷你折线）
帖子 486   快照 2148              本轮互动 +128 ↗
采集轮次 96  字段覆盖 96%          上次 11-07 19:40   下次 20:10

帖子流水                            最近 200 条 · 平台指标：赞 评论 转发
[搜索内容…]                                  双击 / ↵ 打开原帖
┌ 发布时间 ┬ 赞 ┬ 评论 ┬ 转发 ┬ 内容 ──────────────────────┐
│ 11-07 22:14│ 486 │  32 │  18 │ 深夜草图：第 12 版角色动作… │
└───────────────────────────────────────────────────────────┘
```

改动与解决的问题：

1. **动作分层**：`采集当前` 为唯一主按钮（墨底），`采集全部`/`生成报告` 为次按钮，`设置` 降为文字按钮。（H3）
2. **统计分两层**：库存（帖子/快照/轮次/覆盖）与时效（本轮互动/上次/下次）分开，数字用衬线 28–34px，标签等宽 9px；覆盖度旁注明“本轮字段完整率”。（H1、H2）
3. **账号指标上屏**：直接读取 `accounts.csv` 的 followers/following/posts_count/likes_total；平台不提供的指标显示“—”，不隐藏整块。（H5）
4. **表格工具条**：数量、搜索、动态列说明、“双击/回车打开原帖”；列头用完整词（赞/评论/转发/收藏/浏览），无该指标的平台不渲染列。（H4、R4）
5. **空态分级**：
   - 未配置账号 → 提示“先在设置填写账号与会话锚点”，按钮「去设置」
   - 已配置无数据 → 三步引导「1 采集 → 2 生成报告 → 3 长期观察」，按钮「采集当前」
   - 采集中 → 骨架行 + 进度提示
6. **行内详情**：内容列两行截断 + 悬停浮层显示完整文本与帖子 ID；行尾出现“↗”打开原帖。（R1）

状态：

| 状态 | 表现 |
| --- | --- |
| 未启用平台 | 顶部横幅“未启用 · 不参与调度”，按钮「去启用」，统计与表格置灰 |
| 未配置 | 横幅 + 「去设置」，空态优先展示配置引导 |
| 采集中 | 主按钮变为“采集中…”并禁用，统计带右侧出现金色进度条 |
| 失败 | 底部状态条朱红 + 「查看详情」跳运行监控 |

### 5.3 02 运行监控

**目标**：把现有“一行状态”升级为可追溯的运行视图，回答“这一轮跑到哪了、哪个平台失败、为什么、什么时候恢复”。

```text
本轮  ·  运行中 / 已完成 / 等待下一轮             [立即采集全部]
进度：X ✔ ─ Instagram · 跳过 ─ 小红书 ─ 微博 …

平台状态卡（网格）
┌ X           [采集中]  已用时 00:12   ┐
│ 上次 19:40  新增 12 · 快照 48 · 覆盖 96% │
├ Instagram   [冷却中]  20:35 后重试        ┤
│ 失败 LoginRequired：会话过期  [更新锚点]   │
├ 小红书      [未配置]  账号/会话缺失 [去设置] │
└────────────────────────────────────────┘

事件日志                                       [全部|错误|跳过] 清空
21:40:02  INFO  x         采集中…
21:40:14  OK    x         新增 12 · 快照 48 · 覆盖 96%
21:40:16  WARN  instagram 冷却中，20:35 后重试
21:40:18  ERR   weibo     429 限流 · 已冷却 30 分钟
```

改动与解决的问题：

1. 直接消费 `scheduler.platform_state()` 与事件流（`platform_status/done/error/skip/round_done/need_config/log`），把已有数据可视化。（S2）
2. 每个平台一张卡：状态标签 + 耗时 + 上次结果 + 失败类型 + 冷却倒计时 + 对应动作（更新锚点 / 去设置 / 重试）。
3. 事件日志按级别着色并带**文字级别**（INFO / OK / WARN / ERR），不只靠颜色。（S5）
4. “本轮完成”摘要保留，但落到日志首行，可回看。（S1）
5. 失败提示与 `http.py` 的错误类型一致：`login → 更新会话锚点`、`challenge → 可能触发风控`、`rate_limit → 触发限流`。

## 6. 状态与反馈规范

| 场景 | 视觉 | 文案 | 动作 |
| --- | --- | --- | --- |
| 就绪 | 灰点 + `IDLE` | “就绪 · 上次 19:40 · 下次 20:10” | — |
| 采集中 | 金点 + `BUSY` + 进度 | “X 采集中… 12s” | 采集按钮禁用 |
| 成功 | 青点 + `OK` | “X 新增 12 · 快照 48 · 覆盖 96%” | 「查看日志」 |
| 跳过（冷却） | 金点 + `SKIP` | “冷却中，20:35 后重试” | 「立即重试」 |
| 失败（登录） | 朱红 + `ERR` | “会话过期，请更新锚点” | 「更新锚点」 |
| 失败（限流/风控） | 朱红 + `ERR` | “触发限流，已冷却 30 分钟” | 「运行监控」 |
| 未配置 | 虚线徽标 + `SETUP` | “账号或会话缺失” | 「去设置」 |
| 无数据 | 虚线空态卡 | “还没有帖子数据” + 三步 | 「采集当前」 |
| 报告生成中 | 按钮转“生成中…” + 吐司 | — | 生成完成后自动落列表 |

通用规则：

1. 状态必须**颜色 + 文字**双编码；
2. 全局状态条永久显示最近一条，吐司只显示 6 秒；
3. 错误必须提供“下一步动作”，不能只有错误字符串；
4. 空态必须解释“为什么空”和“怎么填”，不只写“暂无数据”。

## 8. 实施建议（不含代码改动）

按“零新增数据源 → 复用已有能力”的顺序推进：

**阶段 A｜外壳与反馈（S）**
`theme.py` 扩展令牌与状态色；`panel.py` 换成左栏 + 底部状态条 + 吐司；空态分级。风险最低，先统一观感。

**阶段 B｜观测台重排（M）**
统计带拆两层、账号指标条、表格工具条与动态列头。保持 `refresh_*` 数据函数不变，只改渲染。

**阶段 C｜运行监控（M）**
直接消费 `scheduler.poll()` 已有事件与 `runs.csv`；冷却倒计时用 `platform_state()["cooldown_until"]`。不需要改调度线程。

**阶段 D｜数据分析与报告历史（L）**
`tk.Canvas` 实现四类图；报告历史扫描目录。注意：应用内图表与 `report.py` 必须共享同一套区间/口径，避免数字对不上。

**阶段 E｜设置改版（M）**
双栏 + 脏状态 + 内联校验；保存逻辑保持 `save_config` 的现有字段边界。

**阶段 F｜桌宠（S）**
气泡两级、状态点、菜单分组；不改动画与拖拽逻辑。

**统一约束**

- 不新增数据库、不新增网络请求、不改变 `config.json` 字段；
- 应用内所有数字必须来自 `store.stats()` / `analysis.build()` / `analysis.deltas()`；
- 报告 HTML 仍是唯一“可导出/可打印”产物，应用内图表只做预览；
- 新配色先落到 `theme.py`，不要在页面里散落十六进制值。
